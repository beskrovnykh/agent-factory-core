# Обслуживание памяти: чем мерить и когда вмешиваться

Память портится сама. Не от ошибок, а от работы: сессии дописывают записи, записи дублируются, индекс растёт, и в какой-то момент методология перестаёт доезжать до роли — **молча**. Так на client-b роль проверки четверо суток не видела определения готовности.

Эта страница — приборы и пороги. Всё, что ниже, прогоняется за минуты и даёт числа, а не ощущение. Замеры в примерах сняты 14.09.2026 (DEV-85) и годятся как база: следующий прогон сравнивают с ними.

## Что именно портится

| болезнь | как проявляется | чем видно |
|---|---|---|
| индекс растёт | методология вытесняется из контекста | размер `MEMORY.md` на роль |
| записи дублируются | два рецепта одного и того же расходятся | пары с общим предметом |
| записи распухают | сессия платит за чтение больше, чем за индекс | размер файлов и что читают |
| роли слепы друг к другу | нужное знание есть, но не у той роли | пересечение имён между каталогами |

Общее у всех четырёх: **отказ бесшумный**. Ни одна не даёт ошибки, все дают тихо ухудшающийся результат.

## Прибор 1. Сколько роль получает в контекст

Главное число. Считается на хосте, где стоит раннер.

```bash
cd ~/agent-runner-<инсталляция>
./.venv/bin/python -c '
import os, sys
for line in open("/home/ubuntu/.agent-runner-<инсталляция>-env"):
    line=line.strip()
    if not line or line.startswith("#") or "=" not in line: continue
    k,_,v = line.partition("="); os.environ[k.strip()]=v.strip().strip("\"").strip("'"'"'")
sys.path.insert(0,"."); import runner
for role in ("work","verify","intake","incident"):
    idx=os.path.getsize(os.environ["AGENT_MEMORY_STORE"]+"/agent-%s/MEMORY.md"%role)
    blk=len(runner.memory_layers(role).encode())
    meth=sum(1 for l in runner.memory_layers(role).splitlines()
             if l.startswith("- ") and "/methodology/" in l)
    print(f"{role:9} индекс {idx:6} + блок {blk:6} = {idx+blk:6} Б | методология {meth} страниц")
'
```

**Пороги.** Наблюдавшийся потолок чтения — 24 400 Б (DEV-29).

| итого в контекст | что это значит |
|---|---|
| до 60% потолка | здорово |
| 60–85% | жить можно, свёртку планировать |
| выше 85% | роль в постоянной обрезке, свёртка нужна сейчас |
| **методология 0 страниц** | **авария: роль работает вслепую, чинить немедленно** |

Число страниц методологии у ролей РАЗНОЕ и это норма (DEV-92): страницы адресованы полем `roles`, `work` получает все, `incident` и `intake` — только общие (без адреса). Ноль — по-прежнему авария.

Последняя строка важнее остальных вместе взятых. Броня в 4 КБ (`METHODOLOGY_FLOOR`) её теперь не допускает, но если поле появилось — значит броню кто-то обошёл или сломал.

Осторожно с интуицией: **`AGENT_MEMORY_INDEX_MAX` проектный индекс не ограничивает.** Его грузит сам claude по симлинку, а переменная делит остаток между методологией и слоем о человеке. Уменьшение переменной уменьшает долю методологии, а не контекст. Рычаги на индекс два: число записей и `runner.INDEX_DESC_MAX`.

## Прибор 2. Что сессии на самом деле читают

Без него свёртка идёт вслепую: непонятно, за что платим.

**Считать по глаголу команды, а не по упоминанию имени.** Имя файла попадает в транскрипт уже потому, что стоит в индексе — наивный подсчёт даёт «100% сессий» и бессмысленную медиану. Эта ошибка была допущена и выброшена при первом замере.

```bash
python3 - <<'PY'
import glob, json, os, collections, statistics, re
tr=glob.glob("/home/ubuntu/agent-work-<инсталляция>/*/transcript.jsonl")
store=os.environ.get("AGENT_MEMORY_STORE","/home/ubuntu/agent-memory-<инсталляция>")
base={}
for root,_,fs in os.walk(store):
    if "_before" in root: continue
    for f in fs:
        if f.endswith(".md") and f!="MEMORY.md": base[f]=os.path.getsize(os.path.join(root,f))
def walk(o,out):
    if isinstance(o,dict):
        if o.get("type")=="tool_use": out.append(o)
        for v in o.values(): walk(v,out)
    elif isinstance(o,list):
        for v in o: walk(v,out)
READ=re.compile(r"\b(cat|head|tail|less|sed -n|bat)\b")
WRITE=re.compile(r"(>\s*\S+\.md|tee |cp |mv |rm )")
cnt=collections.Counter(); per=collections.defaultdict(int); sess=set()
for t in tr:
    for ln in open(t,errors="ignore"):
        try: rec=json.loads(ln)
        except Exception: continue
        uses=[]; walk(rec,uses)
        for u in uses:
            if u.get("name")!="Bash": continue
            cmd=str((u.get("input") or {}).get("command",""))
            if "agent-memory" not in cmd: continue
            if WRITE.search(cmd) or not READ.search(cmd): continue
            for n in {x for x in re.findall(r"([A-Za-z0-9_\-]+\.md)", cmd) if x in base}:
                cnt[n]+=1; per[t]+=base[n]; sess.add(t)
print(f"сессий читало память: {len(sess)}/{len(tr)} ({100*len(sess)/max(len(tr),1):.0f}%)")
print(f"обращений {sum(cnt.values())}, файлов {len(cnt)} из {len(base)}")
if per: print(f"байт на читавшую сессию: медиана {statistics.median(per.values()):.0f}")
big=[n for n in base if base[n]>4000]
print(f"записей >4 КБ: {len(big)}; их доля в обращениях "
      f"{100*sum(cnt[n] for n in big)/max(sum(cnt.values()),1):.0f}%, "
      f"в байтах {100*sum(cnt[n]*base[n] for n in big)/max(sum(cnt[n]*base[n] for n in cnt),1):.0f}%")
for n,c in cnt.most_common(10): print(f"   {c:3}x {base[n]:6} Б  {n}")
PY
```

База 14.09.2026 на client-b: читает 84% сессий, медиана 12 918 Б на сессию. То есть память стоит ≈ 12 КБ индекса всегда плюс ≈ 13 КБ заметок почти всегда. **Файлы — бо́льшая половина счёта, а не довесок.** 15 записей крупнее 4 КБ дали 21% обращений и 34% прочитанных байт: свёртка крупных срезает треть читаемого объёма.

## Прибор 3. Дубли и слепота ролей

`MEMORY.md` и подкаталоги (`_before-migrate`, `_before-index-rebuild`) записями не являются и из выдачи исключаются — иначе они попадают в каждый ответ и читаются как находка.

```bash
S=~/agent-memory-<инсталляция>
entries() { ls "$1"/*.md 2>/dev/null | xargs -n1 basename | grep -v '^MEMORY\.md$'; }

echo "— записи на диске против строк индекса (расхождение = индекс не пересобран) —"
for d in $S/agent-*; do
  f=$(entries "$d" | wc -l | tr -d ' ')
  l=$(grep -c '^- \[' "$d/MEMORY.md" 2>/dev/null); l=${l:-0}
  drop=$(grep -l '^drop: true' "$d"/*.md 2>/dev/null | wc -l | tr -d ' ')
  printf '%-16s файлов %3s (из них выключено %s), строк %3s %s\n' \
    "$(basename $d)" "$f" "$drop" "$l" "$([ "$((f-drop))" -eq "$l" ] && echo ок || echo 'РАСХОЖДЕНИЕ — пересобрать индекс')"
done

echo "— пересечение имён между ролями (ноль = роли слепы друг к другу) —"
comm -12 <(entries $S/agent-work | sort) <(entries $S/agent-verify | sort)
echo "  (пусто — это НЕ норма, см. «слепота ролей» ниже)"

echo "— кандидаты в дубли: общий хвост имени —"
ls $S/agent-*/*.md | xargs -n1 basename | grep -v '^MEMORY\.md$' \
  | sed 's/\.md$//' | awk -F- '{print $NF}' | sort | uniq -c | sort -rn | awk '$1>1' | head
```

## Что делать по симптому

**Индекс за 85%.** Свёртка содержания. Не потолком строки — он уже выбран замером и запаса не создаёт: при 60+ записях индекс упирается в их число.

**Дубли.** Не сброс, а **слияние**. Проверено на пяти парах: ни одна не была чистым дублем, в каждой была грабля, которой в каноне нет. Порядок: выписать утверждения дубля списком → отметить отсутствующие в каноне → дописать в канон → пометить дубль `drop: true` с указанием канона → **построчно проверить, что каждое утверждение уцелело**. Файл не удалять.

Перед слиянием проверить, что это вообще дубль: если «канон» лежит **у другой роли** или **в другом сторе** — это не избыточность, а нехватка кросс-ролевой видимости, и сброс оставит роль без знания. Из девяти кандидатов так отсеялись четыре.

**Крупные записи.** Разбирать на части по правилу «одна запись — один предмет». Средняя заметка 2,6–3,0 КБ, и это уже вдвое больше замысла.

**Слепота ролей.** Поле `roles` во frontmatter. Физическое перемещение файла — почти всегда потеря: заметка «тест проходит вхолостую» нужна и проверке (отличить настоящую проверку), и работе (такой тест не написать).

## Кто это делает

**Не рабочая сессия.** Указание «сожми свой индекс», адресованное той же сессии, которая в этот момент сдаёт задачу, за четверо суток не выполнила ни одна. Указание без исполнителя, срока и проверки механизмом не является.

Свёртка — отдельный прогон: вход read-only, выход — **предложенные правки**, которые подписывает человек. До того, как такой прогон появится, её делают руками по этой странице.

## Чего не делать

- **Не резать по числу обращений.** 38 записей из 104 не читались ни разу — но прибор видит факт вызова, а не пользу: редкая и ценная запись неотличима от мусорной.
- **Не удалять.** Выключают `drop: true`, файл остаётся на диске; прежний индекс уводится в `_before-index-rebuild/`.
- **Не править `MEMORY.md` руками.** Он собирается программой из полей; правка переживёт до следующей сборки.
- **Не заводить крон переверификации.** Отраслевой нормы нет, инвалидация идёт на записи.

## Когда мерить

Прибор 1 — после каждого выката раннера и при подозрении, что роль работает не по правилам. Приборы 2 и 3 — раз в пару недель или когда прибор 1 показал больше 85%.
